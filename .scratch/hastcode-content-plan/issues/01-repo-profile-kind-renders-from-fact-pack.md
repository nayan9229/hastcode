# 01: Repo Profile kind renders from a Fact Pack

**What to build:** An Author can add an Explainer with `kind: repo-profile` and a `repo: owner/name` frontmatter key, drop a Fact Pack JSON file beside it, and get a page at `/{vertical}/{slug}/` whose header card shows what the repository is, who it is for (new optional `who_for` key), stars, license, primary language, latest release and last commit, all taken from the Fact Pack. The piece appears in its Vertical hub, the home page, feeds, search and a new "Repo Profiles" kind page, with the kind badge in listings. The Fact Pack shape (spec "Content model") is defined in this ticket and shared with ticket 05; the test fixtures gain a valid Repo Profile and a valid Fact Pack. A sourced hero is still required here (ticket 04 removes that).

Spec: `../spec.md` ("Content model", User Stories 1, 2, 13, 14, 23, 24). Glossary: Repo Profile, Fact Pack. ADR-0005 governs.

**Blocked by:** None (can start immediately; queue behind publish-v2 tickets 04 and 09 and the merge of `integration/publish-v2`)

**Status:** resolved

- [x] `kind: repo-profile` is accepted; the frontmatter error for unknown kinds names four kinds
- [x] `repo` is required for a Repo Profile and a build error on any other kind; `who_for` is optional on a Repo Profile and rejected elsewhere
- [x] A Fact Pack beside the Markdown, named after it, is loaded; missing, unparsable, or naming a different repository than `repo` is a build error naming the file and rule; fetched more than 30 days ago is a warning
- [x] The page renders at the Vertical URL with the header card fields above, no layout shift (fixed-height card), and the existing byline, dates and AI-assistance note
- [x] Kind page "Repo Profiles" lists Profiles across Verticals newest first; listings show the "Repo Profile" badge; the kind description is the glossary sentence
- [x] Fact Pack field names follow the spec, including the exchange-JSON names where they overlap (`slug`, `url`, `name`, `language`, `license`, `stars`, `latest_release`, `manifests`) and `needs_review` on the license
- [x] Fixture helpers provide a valid Repo Profile and a valid Fact Pack; every existing builder test still passes

## Implementation notes

Built test-first at the builder seam; every criterion has a test in `builder/repo_profile_test.go` (nine tests, plus the amended the existing four-kinds message test in `builder/frontmatter_test.go`). `make check` passes.

- **Kind.** `content.RepoProfile` (`kind: repo-profile`). The unknown-kind message now reads "must be one of case-study, concept, comparison, repo-profile".
- **Frontmatter.** `Explainer.Repo` (`repo`, owner/name, required on a Repo Profile, rejected elsewhere; the shape is checked) and `Explainer.WhoFor` (`who_for`, optional on a Repo Profile, rejected elsewhere). All under rule `frontmatter`.
- **Fact Pack type.** `content.FactPack` in `internal/content/fact_pack.go` (package `content`, so the fetch command of ticket 05 reuses it). Flat repository fields plus `License`, `Release`, `Contributors`/`Contributor`, `RepoFiles`, `READMERef`, `Stargazers`. JSON keys: `fetched_at`, `slug` (owner/name; must equal `repo`), `name`, `url`, `description`, `homepage`, `topics`, `license` {`spdx_id`, `name`, `url`, `needs_review`} or null, `default_branch`, `language`, `languages` (bytes), `stars`, `forks`, `watchers`, `open_issues`, `created_at`, `pushed_at`, `latest_release` {`tag`, `name`, `date`, `url`, `prerelease`} or null, `releases` (latest ten, newest first), `contributors` {`total`, `top` [{`login`, `url`, `contributions`}]}, `files` {`readme`, `license`, `security`, `contributing`, `code_of_conduct`, `ci` [], `manifests` [], `dockerfile`, `docs`, `examples`; paths, "" = absent}, `readme` {`url`, `sha`}, `stargazers` {`count`} (reserves the place for history), `sources` []. No `omitempty`, so a Refresh diff never changes shape. `ParseFactPack` rejects unknown keys.
- **File naming.** `content.FactPackFile(markdownFile)`: same path with `.json` instead of `.md`, beside the Markdown (`explainers/<vertical>/<slug>.json`). The fetch command must write there.
- **Steps and rules.** `step_load_fact_packs.go` (load 22; rule `fact-pack` for missing or unparsable, attributed to the Markdown file, message names the JSON file) and `step_validate_fact_packs.go` (validate 15; `fact-pack-repo` error when `slug` differs from `repo`; `fact-pack-stale` warning when `fetched_at` is more than 30 days before `cfg.Now`). Loaded Fact Packs live in `site.factPacks` by content file.
- **Header card.** Component `views.RepoProfileHeaderCard(views.RepoProfileCard)` in `internal/views/partial_repo_profile_card.templ`, rendered in the article header in place of the standalone `p-summary` (the card's "what it is" cell is the `p-summary`). Markup: `div.repo-profile-card.box` > `p.repo-profile-repo` (repository link) + `dl` with one `div[data-fact=what|who-for|stars|license|language|latest-release|last-commit]` per fact. Fixed height through `--repo-profile-card-height` (360px, 300px from 48rem) with `overflow: hidden` and line-clamped text rows. Stars render with thousands separators (`humanInt`). Absent facts render as "not found" (license, language) or "none yet" (latest release); a `needs_review` license renders as "not classified", never as NOASSERTION. Mapping lives in `builder/repo_profile.go` (`repoProfileCard`, `licenseLabel`, `factNotFound`), the home for ticket 03's Signals and Changelog mapping too.
- **Kind page and badge.** `explainerKinds` gained {"Repo Profile", "Repo Profiles", "Explainers that evaluate one open-source repository: what it is, how it is built, and whether you should adopt it."}; `/explainers/repo-profile/`, the badge and the home link follow from it.
- **Fixtures.** `buildtest.ValidRepoProfile()` (apache/iggy in distributed-systems, the spec's heading order with five FAQ H3s, the AI-assistance note as a blockquote, a sourced 1600x900 hero, `Repo`, `WhoFor`, `FactPack: &ValidFactPack()`), `buildtest.ValidFactPack()` (fixture struct with `JSON()` that spells the keys by hand), `Tree.WithRepoProfile(e)` (writes the Markdown, hero and JSON). `Explainer` gained `Repo`, `WhoFor`, `FactPack *FactPack`. Drop the JSON with `tree.Without(file)` or `e.FactPack = nil`; corrupt it with `tree.With(file, bytes)`.
- **AI-assistance note.** The builder renders no per-article note today; the Editorial Policy's note is Author-written prose. The test asserts the fixture's blockquote renders in the body, which is how every Explainer carries it. Nothing new was built for it.
