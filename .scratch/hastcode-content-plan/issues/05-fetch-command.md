# 05: Fetch command

**What to build:** The Author runs one command with `owner/name` and the path of the Profile's Markdown. It fetches the Fact Pack from the GitHub REST API in at most ten calls (repository, languages, latest ten releases, contributors list with total count, root and `.github` trees for the file flags, README blob reference, stargazer count), writes the JSON beside the Markdown with stable key order and indentation, and writes the README text to the builder's cache directory for drafting. GitHub's `NOASSERTION` license sets `needs_review` instead of failing. The command reads one token from the environment (the variable GitHub Actions provides), sends an identifying User-Agent, honours `Retry-After` and the primary rate-limit headers with a bounded backoff, and stops with a clear message instead of retrying past the limit; without a token it refuses and says why. A refresh flag walks the content tree, re-fetches every Fact Pack, rewrites only those whose content changed (ignoring fetched-at), prints one line per changed repository saying what changed, and exits with a distinct code when anything changed.

Spec: `../spec.md` ("Fetch command", User Stories 17–20, 31 prerequisites). Research: `docs/research/github-trending-geography-and-data-access.md` sections 2 and 3 (rate limits, endpoints, 202 behaviour of the stats endpoint, security policy detection via tree).

**Blocked by:** 01 (Repo Profile kind renders from a Fact Pack) for the Fact Pack shape

**Status:** resolved

- [x] Against an in-process fake GitHub serving recorded JSON, the written Fact Pack equals a golden file
- [x] A second run against the same responses changes only fetched-at
- [x] Refresh mode over a tree with two Profiles, one changed upstream, rewrites exactly that one, prints its one-line summary, and exits with the "changed" code; nothing changed exits zero
- [x] `NOASSERTION` yields `needs_review: true` and a printed note; a normal SPDX id yields false

## Implementation notes

Built test-first at the fetch seam: 18 tests in `internal/factpack/{fetch,ratelimit,refresh}_test.go` drive `Fetcher.Fetch`/`Fetcher.Refresh` against the in-process GitHub of `fake_test.go` (recorded JSON in `testdata/github/<repo>/*.json`, one file per endpoint, hand-written from the REST docs; a missing file is a 404). Golden Fact Pack: `testdata/apache-iggy.json`. The command's main is thin and untested (spec "Testing Decisions"); the exit-code mapping is the `len(report.Changes) > 0` of the tested `RefreshReport`. `make check` passes.

- **Command.** `cmd/fetch`: `go run ./cmd/fetch -repo owner/name -markdown <file>` or `go run ./cmd/fetch -refresh`. Flags: `-repo`, `-markdown`, `-refresh`, `-content` (default `content`; the refresh walk), `-cache` (default `node_modules/.cache/hastcode`, the builder's build-cache default, spelled again here because the command does not import `builder`, so it needs no `make generate`). Ctrl-C cancels a backoff wait. Makefile: `make fetch REPO=owner/name MD=<md>`, `make refresh` — both build `node_modules/.cache/hastcode/bin/fetch` first because `go run` reports every non-zero status as 1. **Ticket 06**: the workflow must run the built binary (or `make refresh`) and test the status for 3, never `go run ./cmd/fetch -refresh`.
- **Exit codes.** 0 done (refresh: nothing changed); 1 a fetch or write failed (`GitHub rate limit reached: …`, network, I/O; in refresh mode the Fact Packs rewritten before the failure stand); 2 usage (bad flags, `GITHUB_TOKEN` unset); 3 refresh rewrote at least one Fact Pack.
- **Environment.** `GITHUB_TOKEN` only (`github.EnvToken`), refused when unset with a message naming it. User-Agent `hastcode-fetch/1 (+https://hastcode.com; Repo Profile Fact Packs)` (`github.UserAgent`). Requests are serial.
- **Packages.** `internal/github`: `NewClient(getenv) (*Client, error)`, `Client.Get(ctx, path, v any) (http.Header, error)`, `LastPage(header)`, `ErrNotFound` (404), `*RateLimitError` (the documented stop), `*StatusError`. Rules: 403/429 with `Retry-After` waits that long; with `X-RateLimit-Remaining: 0` waits until `X-RateLimit-Reset`; a body naming the rate limit without either waits a minute; a wait over `MaxWait` (2 min) or a fourth retry returns `RateLimitError`; 202 retried 3 times (2, 4, 8 s); 5xx 3 times (1, 2, 4 s); 204 is an empty answer. `Sleep`, `Now`, `BaseURL` are fields for tests. `internal/factpack`: `Fetcher{GitHub, CacheDir, Now, Log}`, `Fetch(ctx, repo, markdownFile) (*Result, error)`, `Refresh(ctx, contentDir) (*RefreshReport, error)` with `Change{Repo, File, Facts}` and `Change.String()`, `Marshal(*content.FactPack)`.
- **Calls (nine, ten with `.github`).** `/repos/{o}/{n}`; `/languages`; `/releases?per_page=10` (drafts skipped; `latest_release` = newest non-prerelease among them, no `/releases/latest` call); `/contributors?per_page=10` (top ten as GitHub orders them, bots included); `/contributors?per_page=1` (the `Link` header's `rel="last"` page is the total; no `Link` → the page's length; 204 → 0); `/git/trees/{default_branch}` (root; 404 on an empty repository is "no files"); `/contents/.github?ref={branch}` only when the root tree has a `.github` tree — the contents API because its URL is stable, where a `git/trees/<sha>` URL would change `sources` on every commit and make every Refresh a change; `/readme` (page URL, blob SHA, `path` for `files.readme` and the text base64 in the same answer; `encoding` other than base64 means over 1 MB: noted, not written); `/stargazers/count`, whose shape the docs do not show: decoded as `{"count": N}`; on 404 or a zero count for a starred repository the repository's `stargazers_count` stands in with a printed note and the endpoint is left out of `sources`. `watchers` is `subscribers_count`. License URL is `https://spdx.org/licenses/<id>.html`; `NOASSERTION` → `needs_review: true`, URL "", note "read <license file> by hand". A renamed repository (GitHub's `full_name` differs from the argument) is noted so the frontmatter `repo` gets fixed. `sources` lists exactly the calls that answered, on `https://api.github.com` whatever base URL the client used.
- **Files.** Fact Pack at `content.FactPackFile(markdown)` through `json.Encoder` (two-space indent, HTML escaping off, nil lists written as `[]`, nil `languages` as `{}`, trailing newline). README text at `<cache>/readmes/<owner>/<name>/<README file name>`. The Markdown need not exist; when it does it must parse and be a Repo Profile of that `repo`, else the command refuses before fetching. File flags (`files`) from the root and `.github` listings, root first, name order; CI and manifest names live in `files.go` (`ciDirs`, `ciFiles`, `manifestNames`, `manifestExts`); docs/examples are root directories named docs|doc|documentation / examples|example|samples.
- **Refresh rule.** Walks `content/explainers/**/*.md`, parses each with `content.ParseExplainer` (a frontmatter error aborts naming the file, as the build would), keeps `kind: repo-profile`, in path order. Rewrites only when `Marshal` with `fetched_at` blanked differs from the existing file; an unchanged file keeps its bytes and `fetched_at` (so the builder's `fact-pack-stale` warning on a dormant repository means "no change in 30 days", as the spec's rule implies). A Profile without a Fact Pack gets one, reported as "new Fact Pack"; an unparsable one aborts with a message naming the single-fetch flags. Stdout: one line per change — `owner/name: stars 2468 -> 2600, latest release a -> b, new releases t1, t2, files: security policy added (.github/SECURITY.md) (explainers/<vertical>/<slug>.json)` (`diff.go` phrases: stars, forks, watchers, open issues, last commit, latest release, new releases, contributors, top contributors, each files flag, README, stargazer count, description, homepage, topics, license, default branch, language, languages, rename, sources; fallback "other facts changed") — then `refresh: N Repo Profiles checked, M changed`. **Ticket 06** can build the PR body from the stdout lines matching `^[^ ]+/[^ ]+: `. Notes (NOASSERTION, fallbacks) print as `note: …` lines.
- **`content.FactPack` is untouched**: no fields added, JSON names as ticket 01 left them.
- **Left out on purpose.** No `-api` flag (tests set `Client.BaseURL`); no README copies in CI (the cache is not persisted, and nothing needs it there); no star history.
