# 03: Fact sections, Sources merge and structured data

**What to build:** A Repo Profile page shows two sections the Author never writes. "Signals", inserted after Architecture, lists plain facts from the Fact Pack: last commit date, releases in the last twelve months and the latest release date, contributor count and the share of contributions held by the top ten, open issues, security policy present, license, stars, forks, watchers, and which documentation files and directories exist. No score, no colour grading. "Changelog", inserted after Alternatives, lists the latest releases with tag, name, date and link. The Fact Pack's source URLs join the Sources section once per URL, the way frontmatter sources do. The page's JSON-LD adds SoftwareSourceCode (name, repository URL, programming language, license URL, description) and FAQPage built from the FAQ H3s and their answers, and the allowed-types test admits them. The header card and Signals respect the dark theme.

Spec: `../spec.md` ("Page composition and gates", User Stories 6, 9, 12, 16, 27). Prior art: frontmatter sources merge test, Explainer JSON-LD tests, Mermaid figure insertion.

## Implementation notes

Built test-first at the builder seam; every criterion has a test in `builder/repo_profile_facts_test.go` (ten tests) and the amended `TestExplainerJSONLD_NoUnsupportedTypes` in `builder/structured_data_test.go`. `make check` passes.

- **Placement.** `step_transform_fact_sections.go` (transform 35, after the Sources merge, before the heroes encode) renders each fact section with a templ partial and places it into the body with the new `markdown.Document.InsertHTMLAfterSection(heading, html)` (a builder-HTML block at the end of the named H2 section, like a replaced diagram). The section each follows comes from ticket 02's `repoProfileFactSections` map (Signals after Architecture, Changelog after Alternatives); headings are matched by name, never by index. Because the insert is at the AST level, the page, the full-text feeds and the search index all carry the facts, and the skeleton rule (validate 32) never sees the inserted H2s. Rule `fact-sections` fails a published Profile lacking the section a fact section follows; the skeleton rule makes it unreachable (safety net).
- **Signals.** `views.RepoProfileSignalsSection` (`partial_repo_profile_signals.templ`): `section.signals > h2 + dl`, one `div[data-signal=…]` per fact: `last-commit` (`<time>`), `releases-last-year` (releases dated within the twelve months before `fetched_at`; the Fact Pack lists at most ten, so a full list within the window reads "10 or more"), `latest-release` (tag linking the release page + `<time>`; "none yet" when null, as on the header card), `contributors`, `top-contributors`, `open-issues`, `security-policy` (the path), `license` (SPDX id / "not classified" / "not found"), `stars`, `forks`, `watchers`, `documentation` (README, CONTRIBUTING, CODE_OF_CONDUCT, `docs/`, `examples/`, the ones present). Absent facts read "not found" (`views.FactNotFound`, which `builder.factNotFound` aliases): a zero date, a nil release list, zero contributors, an empty path, no documentation. No score, no grade, no colour by value.
- **Deviation: the top-ten share.** The Fact Pack v1 carries the contributor total and the top ten's contribution counts, not every contribution, so "the share of contributions held by the top ten" cannot be computed. The row states what the data supports and labels it exactly: "spetz holds 81% of the 2,220 contributions by the top 2" (the lead contributor's share of the listed contributions, linked). If the checkpoint wants the true share, the fetch must add a total-contributions fact.
- **Changelog.** `views.RepoProfileChangelogSection` (`partial_repo_profile_changelog.templ`): `section.changelog > h2 + ul`, one `li` per release (tag linking the release page, `span.changelog-name`, `<time>`), sorted newest first (the Fact Pack promises that order; the sort keeps it true), a pre-release carrying `data-prerelease` and the text "pre-release" in `span.changelog-prerelease`. An empty release list reads "none yet", a missing one "not found".
- **Sources.** `mergeExplainerSources` appends a Repo Profile's Fact Pack `sources` after the frontmatter sources as `content.Source{URL: u}` (link text = the URL), through the same `newSources` dedup (trailing slash and surrounding space ignored): a URL already linked in the body or titled in the frontmatter is not repeated, and the feed carries the result.
- **JSON-LD.** `schema.SoftwareSourceCode` (`@context`, `name` = the full name `owner/name`, `codeRepository` = the repository URL, and only when the Fact Pack carries them: `programmingLanguage`, `license` = the license URL (omitted for a `needs_review` license), `description` = the repository description) and `schema.FAQPage` (`mainEntity`: one `Question` per `###` under `## FAQ` in order, `name` = the heading text, `acceptedAnswer.text` = the rendered HTML of the blocks up to the next `###`, e.g. `<p>Not for multi-node deployments yet.</p>`). Both are appended to the Article graph in `explainerPage` (which now returns an error for a Markdown rendering failure) for Repo Profiles only. The schema package doc now names them and keeps HowTo, Speakable and TechArticle absent; the research note's "skip FAQPage" stands for every other kind.
- **Theme.** `.signals` and `.changelog` rules in `site.css` use the brand tokens only; `TestRepoProfile_HeaderCardSignalsAndChangelogUseBrandTokensOnly` greps every `.repo-profile-card`, `.signals` and `.changelog` rule (inside `@media` too) for colour literals and requires a token, on top of the palette rules the design-system tests verify for both themes.
- **Size.** The fixture Profile renders to about 18 KB with both fact sections, three JSON-LD blocks and the Mermaid SVG; `TestRepoProfile_FixtureProfileStaysUnderThe50KBGate` asserts the file size against the 51,200-byte gate.
- **Left for later tickets.** 05: write `sources` as the URLs the fetch reads (they appear verbatim as Sources links). 07: the template must not write Signals or Changelog; FAQ answers become the FAQPage text, so keep them self-contained prose. 08: see the markup and JSON-LD names above when checking the Preview.
